# LION doctor v1: read-only Check-Framework + reco.sh

## Goal

`lion doctor` führt einen eigenständigen, **read-only** Diagnose-Scan der
Maschine aus (frischer `collect_state` + Live-Dateisystemprüfungen) und meldet
den Zustand aller Subsysteme mit `ok`/`warn`/`error`/`skip`. Findet es
Probleme (`warn`/`error`), erzeugt es **genau ein** reviewbares
Behebungs-Skript unter `$XDG_DATA_HOME/lion/recos/`, das der **Mensch** prüft
und ausführt. LION selbst führt nie etwas aus und verändert nichts.

## Scope

**In Scope**

- Ein Kommando `lion doctor` (kein `status`-Subkommando, keine Topic-Subkommandos).
- Read-only Check-Framework mit Registry aus den besitzenden Modulen.
- Fünf Topics: `collectors`, `tools`, `history`, `storage`, `shlib`.
- Vier Zustände `ok`/`warn`/`error`/`skip`; Text- und `--json`-Ausgabe; Exitcodes.
- Artefakt `reco.sh` unter `$XDG_DATA_HOME/lion/recos/`, human-executed.
- Profilabhängige „erforderlich/optional"-Tool-Policy.
- ADR, Doku, Tests.

**Out of Scope** (bewusst, Folgeschritte)

- `--fix` / automatische Ausführung von `reco.sh` — widerspricht dem Design.
- `--strict` (Hochstufen `warn` → Exit 1).
- Topic-Subkommandos (`doctor tools`, `doctor history`, …).
- Retention/Aufräumen der `recos/` (Akkumulation wie History; später evtl.
  `lion reco list`/Prune).
- Neue Collector/Subsysteme.

## Decisions

1. **`doctor` = frischer read-only Scan, nichts persistiert.** `doctor` ruft
   `collect_state(COLLECTORS)` auf und prüft zusätzlich live das Dateisystem.
   Kein `Snapshot` wird geschrieben, kein `scan`-Zustand verändert. Abgrenzung:
   `lion status` = *Vergleich* aktuell↔gespeichert, `doctor` = *Diagnose* der
   aktuellen Maschine + Integrität. Self-contained: funktioniert ohne
   vorherigen `lion scan`.
2. **Ein Kommando.** `lion doctor` ohne Subkommando; alle Topics laufen. Die
   Gruppen-Regel greift nicht (bewusst kein `status`-Subkommando).
3. **Artefakt `reco.sh` in `$XDG_DATA_HOME/lion/recos/`.** LION-eigenes
   Verzeichnis ⇒ die Goldene Regel (ADR 0001: „writes confined to LION's own
   directories") bleibt **formal unverletzt**; die kanonische README-Zusage
   bleibt unverändert. `recos/` liegt direkt unter `$XDG_DATA_HOME/lion/`, neben
   `history/` (`scans/` ist Legacy/entfernt).
4. **LION führt nichts aus, verändert selbst nichts.** `reco.sh` ist eine
   reviewbare Empfehlung und darf die **vollständige** Behebung enthalten, auch
   privilegierte Befehle (`sudo`, Paket-/Systembefehle). Der Mensch liest und
   führt aus. Neue ADR `docs/decisions/0007-doctor-reco-human-executed.md`
   hält das fest (bewusster Kontrast zu 0001, aber vereinbar: 0001 regelt
   *Schreibziele*, 0007 *Empfehlung ≠ Ausführung*).
5. **Non-Goals präzisieren.** Nicht mehr „LION verändert keine Pakete/
   Systemdateien", sondern „**LION führt keine Systemveränderungen aus und
   schreibt nur in eigene Verzeichnisse; es darf Behebungen als reviewbares
   Skript empfehlen, führt sie aber nie aus**" (betrifft
   `ignore/PROJECT_DEFINITION.de.md`, `docs/explanation/write-boundary.md`).
6. **Vier Zustände** `ok`/`warn`/`error`/`skip`. `skip` = „nicht zutreffend /
   optional nicht nötig" (shlib nicht installiert, Nicht-Debian, optionales Tool
   fehlt, noch keine History); zählt nicht negativ, ändert den Exitcode nicht.
   JSON-Wert `warn` (nicht `warning`), Text „Warnung"; `skip`-Text
   „– (nicht zutreffend)".
7. **Exitcodes:** `0` = kein `error` (Warnungen/skips erlaubt), `1` = mindestens
   ein `error`; Usage-Fehler bleibt Typer-`2`.
8. **`error` nur für LIONs eigene, nicht umgehbare Defekte** (beschädigter
   History-Eintrag, `recos/`/Datenverzeichnis nicht schreibbar, mehrdeutige
   shlib-Marker). **Fehlendes (profil-)erforderliches Tool = `warn`**, weil kein
   Tool global erforderlich ist: LIONs Kern (`host`, storage, `history`, `diff`,
   `shlib status`) ist reine Stdlib; Tools reichern nur einzelne Collector/
   shlib-Mutationen an.
9. **Tool-Policy profil-relativ** (Fakten aus frischem Scan):

   | Tool | benötigt, wenn | sonst | fehlend → |
   |---|---|---|---|
   | `lspci` | immer (Quelle der GPU-Erkennung) | — | `warn` |
   | `nvidia_smi` | `gpu_vendor == nvidia` oder `compute_platform == cuda` | `skip` | `warn` |
   | `rocm_smi` | nie (von keinem Collector genutzt) | `skip` (informativ) | nie `warn` |
   | `apt_mark` | Debian/Ubuntu (`host.distribution`) | `skip` | `warn` |
   | `zsh` | nur für `shlib install/uninstall` relevant | für `doctor` `skip` | `warn` nur wenn shlib-Aktion ansteht |

10. **reco-Befehle konservativ.** Nur Befehle, deren Paketname sicher bekannt
    ist, werden als ausführbare Zeile erzeugt (distro-aware, z. B. Debian
    `sudo apt install pciutils` / `zsh`); alles Unsichere (NVIDIA-Treiberpaket,
    apt-mark) wird reiner Kommentar-Hinweis. **Niemals** Ausgaben externer
    Tools in reco-Befehle interpolieren (nur eigene Konstanten) — kein
    Secret-/Injection-Leak.
11. **Datei-Mechanik `reco.sh`:** **eine Datei pro Lauf**; Name
    `<compact-erstscan>.sh` (UTC, `COMPACT_TIMESTAMP_FORMAT` aus Storage),
    Kollisionssuffix `~NNNN` vor `.sh`; Verzeichnis erst bei Bedarf anlegen;
    exklusive Publikation (`os.link`, nie überschreiben, keinem Symlink folgen);
    Modus `700`. Reines `ok` schreibt **keine** Datei (doctor bleibt dann zu
    100 % read-only).
12. **Ausgabe.** Standard (Text): geprüfte Topics, je Topic eine Zeile, Befunde
    mit Abhilfe, Ergebniszeile; bei Problemen zusätzlich der reco-Pfad + „erst
    lesen, dann ausführen". `--show` gibt den reco-Inhalt zusätzlich auf stdout.
    `--json`: nur ein JSON-Objekt auf stdout (deutsche Keys, konsistent zu
    `status --json`/`scan --json`). Laufzeit-Texte Deutsch (wie `status`/`scan`/
    `diagnostics`), `--help`/Epilog Englisch.
13. **`inspect_history` nicht-werfend.** `doctor` darf **nicht**
    `list_entries()`/`load_latest()` nutzen (die brechen beim ersten kaputten
    Eintrag ab). Neue Funktion, die pro Datei einen Status liefert.
14. **Collector-/Tool-Checks besitzen keine Collector-Imports.** Die neuen
    Checks konsumieren nur das fertige State-Mapping (kein Importzyklus).

## Check-API und Registrierung

`src/lion/program/doctor.py` (Framework + Aggregation):

```python
class CheckStatus(StrEnum):
    OK = "ok"; WARN = "warn"; ERROR = "error"; SKIP = "skip"

@dataclass(frozen=True)
class Finding:
    topic: str                 # collectors|tools|history|storage|shlib
    name: str                  # stabil, z. B. "tools.nvidia_smi"
    status: CheckStatus
    message: str               # was geprüft wurde / was falsch ist
    hint: str = ""             # manueller nächster Schritt (Text)
    commands: tuple[str, ...] = ()   # ausführbare reco-Zeilen (nur eigene Konstanten)

@dataclass(frozen=True)
class DoctorContext:
    state: dict[str, dict[str, object]]   # frischer collect_state
    home: Path

Check = Callable[[DoctorContext], Sequence[Finding]]

CHECKS: tuple[Check, ...] = (
    diagnosis.collector_checks,   # state/diagnosis.py
    diagnosis.tool_checks,        # state/diagnosis.py
    storage.history_checks,       # program/storage.py
    storage.storage_checks,       # program/storage.py
    shlib_checks,                 # program/shlib.py
)
```

- `run_checks(ctx) -> list[Finding]` iteriert `CHECKS`, fängt pro Check
  unerwartete Ausnahmen als `error`-Finding (kein Check darf den Lauf
  abbrechen), sortiert deterministisch nach `(topic, name)`.
- `overall(findings) -> CheckStatus` (error > warn > ok; skip neutral).
- `summary(findings) -> dict[str, int]` (`ok`/`warn`/`error`/`skip`).
- `render_text(findings, reco_path)` und `render_json(findings, reco_path)`.
- `render_reco(findings, version, host) -> str` (Header-Kommentare +
  Befund-Blöcke; Befunde ohne `commands` nur als Kommentar).

## Check-Inhalte (v1)

**`collectors`** (`state/diagnosis.py`, aus frischem State): für jeden
kanonischen Collector (`registry.COLLECTORS`) Sektion vorhanden? `status == ok`?
`unavailable`/`error` ⇒ `warn` mit verständlicher Meldung (Sektion-`error`);
sonst `ok`.

**`tools`** (`state/diagnosis.py`): Profil aus `hardware.gpu_vendor`,
`hardware.compute_platform`, `host.distribution`; pro Tool in
`tooling.TOOLS` Policy aus Decision 9 anwenden ⇒ `ok`/`warn`/`skip`; bei
`warn` Abhilfe (distro-aware Kommando, sonst Kommentar).

**`history`** (`program/storage.py`, live, nicht-werfend):
- keine Einträge ⇒ `skip` („Keine History vorhanden").
- pro `*.toml`: `inspect_history()` ⇒ ungültig = `error` mit **Pfad** + Ursache;
  gültig = `ok` (aggregiert „N gültige Einträge").
- Legacy-`scans/`-Verzeichnis vorhanden ⇒ `warn` (wie `status.py`).
- Reihenfolge `zuletzt_bestaetigt` nicht monoton ⇒ `warn`.

**`storage`** (`program/storage.py`, live, **ohne** Schreiben): nächster
existierender Elternpfad von `$XDG_DATA_HOME/lion` per `os.access(..., W_OK)`;
`history/` und `recos/` schreibbar bzw. im beschreibbaren Datenverzeichnis
anlegbar. Kein `mkdir`, kein `.history.lock` anlegen. Nicht schreibbar ⇒
`error`.

**`shlib`** (`program/shlib.py`, live): auf `status(home)` aufsetzen.
`installed == false` ⇒ `skip` + Hinweis (`lion shlib install`). Installiert:
vorhandene `warnings` (fehlende Verzeichnisse, ungültige Exportnamen, Rechte
≠ 600) ⇒ `warn`; `lock == "changed"` ⇒ `warn`; `dash/`-Einträge müssen
Symlinks sein, kaputte ⇒ `warn`. `ValueError` (mehrdeutige Marker, ZDOTDIR) ⇒
`error`-Finding (nicht abbrechen).

## reco.sh — Inhalt

```bash
#!/usr/bin/env bash
#
# lion doctor — Behebungsvorschläge (reco)
# Erzeugt: <ISO-Zeitstempel>
# LION: <__version__>
# Host: <hostname> (<distribution> <distribution_version>)
#
# VOR DEM AUSFÜHREN KOMPLETT LESEN.
# LION führt dieses Skript niemals aus und ändert selbst nichts.
#
set -euo pipefail

# ============================================================
# [tools] tools.nvidia_smi: warn
#   NVIDIA-GPU erkannt, aber nvidia-smi fehlt.
# ============================================================
# Abhilfe (manuell): passenden NVIDIA-Treiber installieren.
```

## JSON-Schema (deutsche Keys)

```json
{
  "status": "error",
  "geprueft": ["collectors", "tools", "history", "storage", "shlib"],
  "befunde": [
    {"topic": "tools", "name": "tools.nvidia_smi", "status": "warn",
     "message": "...", "hint": "...", "commands": ["sudo ..."]}
  ],
  "zusammenfassung": {"ok": 5, "warn": 2, "error": 1, "skip": 3},
  "reco_pfad": "/home/.../recos/2026-...Z.sh"
}
```

`reco_pfad` ist `null`, wenn kein `warn`/`error` vorlag.

## Tasks (geordnet)

1. **`src/lion/program/storage.py`**
   - `get_recos_dir() -> Path` (`get_data_dir() / "recos"`).
   - `HistoryInspection(path, snapshot, error)` + `inspect_history()` (nicht
     werfend, pro Datei).
   - `history_checks(ctx)`, `storage_checks(ctx)` (read-only, ohne Writes).
   - `publish_reco(content: str) -> Path`: `recos/` bei Bedarf anlegen
     (Modus `700`), Temp-Datei schreiben+fsync+`fchmod 0o700`, via `os.link`
     unter `<compact>~NNNN.sh` publizieren, nie überschreiben/Symlink folgen.
2. **`src/lion/state/diagnosis.py` (neu)**
   - Tool-Policy-Tabelle + `_required(...)`; `collector_checks(ctx)`,
     `tool_checks(ctx)`. Keine Collector-Imports (nur State-Mapping lesen);
     `tooling.TOOLS` für die Werkzeugliste nutzen.
3. **`src/lion/program/shlib.py`**
   - `shlib_checks(ctx)` auf Basis von `status()`; `dash/`-Symlink-Prüfung;
     `ValueError` als `error`-Finding.
4. **`src/lion/program/doctor.py` (neu)**
   - `CheckStatus`, `Finding`, `DoctorContext`, `Check`, `CHECKS`,
     `run_checks`, `overall`, `summary`, `render_text`, `render_json`,
     `render_reco`.
5. **`src/lion/command/doctor.py` (neu)**
   - `run(json_output=False, show=False)`: `home` ermitteln (Fehler als
     shlib-Finding, nicht abbrechen), `collect_state(COLLECTORS)`, `run_checks`,
     bei `warn`/`error` `render_reco` + `publish_reco`, Ausgabe, danach
     `raise typer.Exit(code=1)` bei `error`.
   - `--show` nur im Textmodus wirksam.
6. **`src/lion/cli.py`**: `@app.command(epilog=DOCTOR_EPILOG)` `doctor` mit
   `--json` und `--show`; Import `run` aus `command/doctor.py`.
7. **`src/lion/main.py`**: `DOCTOR_EPILOG` (Englisch); `ROOT_EPILOG`-Liste um
   `lion doctor` ergänzen.
8. **Docs**: ADR `docs/decisions/0007-doctor-reco-human-executed.md` (neu);
   `docs/explanation/write-boundary.md` (recos als Schreibziel, „generiert,
   führt nie aus"); `docs/reference/storage.md` (`recos/`, Name, Modus 700);
   neues How-to `docs/how-to/diagnose-with-doctor.md` (Englisch); `README.md`
   (doctor-Zeile); `ignore/PROJECT_DEFINITION.de.md` (Non-Goals, Bestand,
   Kommandolandkarte) und `ignore/ROADMAP.de.md` (Phase 1 doctor).
9. **`just docs`** ausführen (CLI-Referenz ist CI-geprüft, `just docs-check`).
10. **Tests** (siehe unten) schreiben/erweitern.
11. **`SESSION.md` überschreiben, `JOURNAL.md` datiert ergänzen.**

## Tests

`tests/test_doctor.py` (neu), deterministisch, gemockte Collector/Tools und
temporäres `XDG_DATA_HOME`/`HOME` (keine echten GPUs/Dpkg):

- **Alles ok**: keine reco-Datei, Exit `0`, Text „OK"/Ergebniszeile,
  `--json`-Schema.
- **`warn`**: fehlendes erforderliches Tool (Profil gemockt) ⇒ reco-Datei
  angelegt, Exit `0`, Pfad gemeldet, Inhalt enthält Abhilfe; `--show` gibt
  Inhalt aus.
- **`error`**: beschädigte History-Datei ⇒ Exit `1`, Meldung **nennt den
  Pfad**; nicht schreibbares Datenverzeichnis ⇒ Exit `1`.
- **`skip`**: shlib nicht installiert, Nicht-Debian, optionales Tool fehlt ⇒
  `skip`, keine Negativwertung.
- **Read-only-Invariante**: Vorher/Nachher-Vergleich von `history/` und
  `recos/` — keine fremden Schreibzugriffe; ohne Problem entsteht kein
  `recos/`.
- **reco-Mechanik**: Kollision ⇒ `~0001`-Suffix, nie überschreiben;
  Symlink-Ziel wird nicht geschrieben; Modus `700`.
- **Ausgabe**: `--json`-stdout ist reines JSON; Exitcodes 0/1.
- `tests/test_shlib.py`/`tests/test_storage.py` für die neuen
  `*_checks`/`inspect_history`-Pfade ergänzen (gültig/ungültig/leer).

- Gezielt: `uv run pytest tests/test_doctor.py -s`.
- `just docs` → `docs/reference/cli.md` aktuell; `just docs-check` grün.

  an echten Daten).

## Risks / Edge Cases

- **Doppelmeldung** Collector-`unavailable` + Tool fehlt: beide `warn`;
  gewollt (Tool-Check trägt die Abhilfe), kein `error`-Eskalieren.
- **Injection/Secrets**: reco-Befehle ausschließlich aus eigenen Konstanten,
  niemals aus Tool-Ausgaben oder Env-Werten.
- **`--json`-stdout-Reinheit**: Befunde JSON, reco-Inhalt nur mit `--show`.
- **`get_home()`/ZDOTDIR**: als shlib-`error`-Finding behandeln, Lauf nicht
  abbrechen.
- **Determinismus**: Befunde sortiert (topic, name); reco-Zeitstempel ist
  Artefakt-Metadatum, kein State.
- **Laufzeit**: `collect_state` inkl. `packages` (Dpkg/apt-mark) bei jedem
  `doctor`; bewusst (frischer Scan), akzeptiert.
- **recos-Akkumulation**: wächst wie History; Aufräumen ist Follow-up.

## Follow-up (nicht Teil dieses Plans)
